# Dragon DiskForge — Split, Join and Compression Pipelines

This document defines the proven 0.6 Core scope for split/join and bounded transport compression. These APIs are deliberately narrower than full format conversion and remain separate from any future user-visible Create/Convert UX.

## Split sets

`SplitImagePipelineService.SplitToDirectoryAsync` turns one flat source file into a versioned split-set directory.

Safety properties:

- the destination directory must not already exist
- source bytes are read sequentially through a fixed 1 MiB buffer
- a split set is limited to 10,000 parts
- every part receives an SHA-256 digest in `dragon-split-manifest.json`
- part names are generated by the engine and never derived from untrusted path fragments
- all parts and the manifest are staged in a sibling temporary directory
- the final split directory is published only after every staged part and the manifest are complete and flushed
- cancellation before publication removes the staging directory when possible
- once the final same-volume directory rename begins, cancellation is intentionally no longer observed mid-commit

A zero-length source is represented deterministically by one empty part plus the manifest.

## Join

`SplitImagePipelineService.JoinFromDirectoryAsync` accepts only a structurally valid Dragon split set.

Before or during the transactional output write it validates:

- supported manifest version
- declared source size and part geometry
- bounded part count
- non-rooted, non-traversing, unique part filenames
- physical part lengths
- per-part SHA-256 digests
- exact reconstructed byte count

The destination must be outside the source split directory. Final output is published through `SafeOutputService`, so a failed hash check, cancellation, truncated part or other writer failure does not intentionally replace an existing committed destination.

## Whole-file gzip transport compression

`GzipImagePipelineService` provides transactional whole-file gzip compression and decompression.

Compression:

- source is read sequentially through a fixed 1 MiB buffer
- destination publication uses `SafeOutputService`
- source and destination must differ
- progress reaches `1.0` only after final transaction commit

Decompression:

- rejects files shorter than the minimum gzip header/trailer envelope
- validates gzip magic, compression method and reserved header bits before output staging
- requires a caller-provided maximum decompressed byte count
- fails closed if decompressed bytes would exceed that cap
- publishes output only through `SafeOutputService`

The explicit output cap is required so a small compressed input cannot cause unbounded disk growth.

## Sparse-input scope

Dragon DiskForge already has truthful read-only guest-byte readers for the supported QCOW2 and hosted-sparse VMDK subsets. Their proven sparse/unallocated mappings can be materialized to flat RAW through `RawImagePipelineService`.

That is the bounded sparse-input scope completed by the 0.6 foundation. It does **not** mean Dragon DiskForge can write sparse QCOW2/VMDK containers.

## Explicit non-goals

The 0.6 foundation does not claim:

- sparse-container creation or rewriting
- QCOW2 compressed-cluster decoding
- VMDK stream-optimized/compressed extent decoding
- DMG `blkx` compressed payload decoding
- archive formats other than the tested whole-file gzip transport wrapper
- Create/Convert UI enablement

Those capabilities require their own format-specific parser/writer design, tests and product gates before they can become truthful capabilities.

## Validation

`tests/DragonDiskForge.SplitCompression.SmokeTests` covers:

- multi-part split geometry and exact join reconstruction
- zero-length split/join
- existing split destination refusal
- split cancellation before publication
- SHA-256 mismatch rejection with destination preservation
- gzip round-trip correctness
- decompression expansion cap enforcement
- malformed/truncated gzip rejection
- compression cancellation
- source/destination identity rejection
- transaction/staging cleanup checks

The Windows CI gate runs this suite before provider, Explorer, native Windows, Release build and clean-package verification gates.
